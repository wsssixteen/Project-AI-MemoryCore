# RustDesk: apps (e.g. Sourcetree) not visible or not controllable on a remote Windows PC

Date: 2026-10-27. Checked against RustDesk master (commit 59f2953c) and release tag 1.5.0.

**Bottom line:** The best-supported cause is integrity level (UIPI): the app runs elevated while RustDesk runs unelevated (portable, not installed as a service). RustDesk's own source has a message for exactly this case. Fix: install RustDesk on the remote PC, or elevate it. Rendering (WPF / DXGI) is a weaker second lead.

**Observed on PJNBRidhwan, 2026-10-27 (supersedes the elevation lead for this PC):** the fault is on the PC, not in RustDesk. Notepad++'s text area is blank too, and is blank in a local GDI screen capture and in PrintWindow(PW_RENDERFULLCONTENT), so the window itself draws nothing. A fresh Notepad++ with DirectWrite on (`writeTechnologyEngine="1"`) is blank; the same file with DirectWrite off (`"0"`, separate `-settingsDir`) shows the text. So the GPU drawing path (Direct2D) fails on this PC; GDI-drawn parts (menus, toolbars, tabs) work. Sourcetree (WPF, Direct3D) blank is the same class (inferred, not tested). dxdiag: AMD Radeon (integrated, driver 31.0.21921.1000, no problem code) plus a Parsec Virtual Display Adapter (0.45.0.0, Parsec service running, no screen attached). No display-driver reset event (4101) in 3 days. Uptime since 2026-10-20. Why Direct2D fails here is not verified (Parsec adapter or AMD driver state are the leads). Fixes: Notepad++ Preferences, untick DirectWrite (proven); restart the graphics driver with Win+Ctrl+Shift+B or reboot (not tested).

## Remediation order (most likely and least disruptive first)

1. Check whether the failing app is elevated: remote Task Manager > Details > right-click header > Select columns > "Elevated" (inferred method). Concept source: https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-it-works
2. If elevated and RustDesk is portable: install RustDesk on the remote PC (RustDesk shows "Due to UAC, RustDesk can not work properly as the remote side in some cases. To avoid UAC, please click the button below to install RustDesk to the system."). Source: https://github.com/rustdesk/rustdesk/blob/master/src/lang/en.rs
3. If you cannot install: on the remote PC click "Elevate" in the RustDesk connection management window, or "Accept and Elevate" when accepting; accept the UAC prompt. Source: https://rustdesk.com/docs/en/client/windows/windows-portable-elevation/
4. From the controlling side: action menu > "Request Elevation", then pick "Ask the remote user for authentication" or "Transmit the username and password of administrator". Someone on the remote side must still accept the UAC prompt. Domain accounts: `DomainName\Username`. Sources: https://rustdesk.com/docs/en/client/windows/windows-portable-elevation/ and https://github.com/rustdesk/rustdesk/wiki/FAQ
5. Unattended portable: rename the exe to include `-qs-` or end `_qs.exe` (1.4.6 and later; 1.2.0 to 1.4.5: name ends with `qs.exe`), run it, accept UAC once. Or right-click > Run as administrator. Source: https://rustdesk.com/docs/en/client/windows/windows-portable-elevation/
6. Stop running the app as administrator if it does not need it: right-click exe > Properties > Compatibility > untick "Run this program as an administrator" (menu path inferred; no Atlassian source says Sourcetree needs admin). UIPI background: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput
7. If the picture is black (not just unclickable): in the RustDesk session toolbar or Settings turn off "Use hardware codec", try VP9. Source: https://rustdesk.com/blog/rustdesk-connected-waiting-for-image
8. Update RustDesk on both ends. Source: https://rustdesk.com/blog/rustdesk-connected-waiting-for-image
9. Update the GPU driver on the remote PC. Source: https://rustdesk.com/blog/rustdesk-connected-waiting-for-image
10. Last resort for one blank app: set WPF `DisableHWAcceleration` = 1 and restart the app. Source: https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/graphics-rendering-registry-settings
11. Not recommended: a community comment (not a maintainer) suggests `PromptOnSecureDesktop` = 0 to see the UAC screen; the same comment says keyboard and mouse stay locked afterwards. Source: https://github.com/rustdesk/rustdesk/issues/104
