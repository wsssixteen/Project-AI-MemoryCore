## What I learned / slips
- **push ≠ deploy** (the day's big one). A `git push` to `mlk/int-env` puts the fix on the branch, not on the running server. A fresh document generated today rendered the OLD common template despite the branch carrying #255170 — because the deployed WAR predated it. Always confirm a real WAR rebuild+deploy before treating an env-branch fix as live.
- **Two over-claims I had to walk back myself** (verification slips): (1) said the tajuk was bound to `tujuanPermohonan` — miya's photo showed it's a 4-CC construct; the real answer was `tajukRisalat`. (2) said "image CCs never render in a page header" — the page-1 letterhead logos are runtime image CCs that DO render in a header, so the barcode claim was too strong. Both times I inferred structure from the qa_doc/memory instead of opening the actual docx XML first.
- **Font in a template CC is not a code concern**: `populateBandarPekanMukim` returns plain text with no font; the font lives entirely in the docx run properties. The fix was `cs`=Times New Roman → Arial in Word, not code.
- **Gate friction was real but the gates were right**: compile-gate + deploy-guard each blocked a company-branch action; both bypass tokens are read from miya's message, not my command. On the binary merge conflict, I proved int-env's template was byte-identical to the merge base before taking the ticket version — so nothing was discarded.
