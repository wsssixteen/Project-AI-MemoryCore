## What I learned

- **eSOKONGAN tickets don't always live on `mlk/esokongan/<num>`.** #271639 is an eSOKONGAN ticket
  but Aaron pushed the fix to **`mlk/internal/271639`**. The recon script's tracker→branch-shape
  guess missed it (probed the esokongan name, found only an unlabelled merge commit); a git-log grep
  + `ls-remote '*271639*'` found the real branch. The skill's "verify each against ls-remote, never
  assume" rule is exactly why this resolved — the branch-shape table is a hint, not truth.
- **The deployed version footer can't prove a fresh build (V6b).** The version-bump commit and the
  fully-merged HEAD both render the identical footer string, so a stale checkout looks convincing.
  The only proof is matching the build log's checkout SHA against the pushed HEAD — footer values
  matching is strong evidence, not proof.
