## What we did

The carry-forward from yesterday said: extend the framework so content controls inside Word text boxes become findable, ship it on `mlk/qa/262370` before that branch merges. The note predicted a "2-4h XPath drop-in." It wasn't that.

The fix went through three versions before it was right:

- **v3** — I assumed `JaxbXmlPart.getBinder()` existed and built a fresh `Context.jc.createBinder()`. The server log told the truth: `binder.getXMLNode returned null` on every part. A fresh binder has no JAXB↔Node associations.
- **v4** — switched to the part's own binder via `JaxbXmlPartXPathAware.getJAXBNodesViaXPath()`. A standalone probe proved it found the text-box SDT. But it only worked on the *Part path* — and the actual header flow doesn't use that path. `headerSurat1` is an external content control; the framework injects it by passing a `CTSdtContentBlock` (no binder) into `getAllElementFromObject`. v4 never fired there. The generated output proved it: the txbxContent CC was present but empty.
- **v5** — the correct shape. When the recursion hits a `Drawing`/`Pict` (the non-ContentAccessor wrappers that block text-box access), fire a `TraversalUtil` sub-walk — docx4j's own tree walker, which descends `Pict → VML CTShape → CTTextbox → w:txbxContent`. It runs from *inside* the recursion, so it covers both the Part path and the injection path. A third probe — calling the real v5 method on the real injection path — proved it: `logoPejabatTanah` found.

Then the HeaderSurat.docx side. みや wrapped the logo CC in a text box. The anchor kept escaping the `headerSurat1` content control — and the framework only injects what's *inside* that control, so the logo vanished from the output. I did the XML move to put the anchor paragraph back inside the CC. After that, plus みや sizing the box and setting No Fill — the logo rendered. He said he was very happy with the result.

Branch closed out: `mlk/qa/262370` delete-recreated, commit `6b1459a0eb` (v5 + the text-box HeaderSurat.docx) supersedes the old `bcdcadadb3` vAlign approach.
