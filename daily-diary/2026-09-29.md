## What happened
- Closed out the laptop RAM incident that started 2026-09-22. The laptop had hung at 93-96% RAM because every Claude session started all 21 database connectors and 233 finished sessions were never archived. The db-gateway built on 09-28 now serves all 20 database connectors from one shared process that starts a database only when it is queried. After miya restarted, memory in use was 12 GB instead of 60.
- miya asked whether this belongs in monitoring and system-rules, and whether to research it. A web researcher and a system auditor ran in parallel, then I appraised the result. Rule 7 (resource footprint declared at birth) went into system-rules. The forge and the birth gate now refuse a new component that does not state its cost.
- The audit found three more costs: 36 hooks that run on every prompt and 42 when each reply ends (about 60-70 node processes each time), 56 worktrees taking 15 GB, and 64 MB of telemetry that is never rotated. The WaRead watcher had crashed and nothing noticed. All of these are listed in todo Q1.

## What I learned
- Every process is traceable by its parent. I told miya "orphans" and "can't trace" before I checked, and both were wrong. Measure live first.
- A written rule is not enough on its own. Rule 6 (retention) existed, yet telemetry was never rotated. Rule 7 shipped with its gate on the same day.
- miya rejects monitoring that only draws a screen. It has to fire on its own and act.
- Task Scheduler runs tasks below normal priority by default, and under memory pressure that starves a daemon for minutes.
