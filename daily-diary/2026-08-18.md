# Daily Diary — 2026-08-18 (Tuesday)

## What happened

miya was verifying eSOKONGAN **#275009** on MLKIT and hit an unexpected tugasan: PT `PTMLK/01/L/PT/2026/23` (aplikasi 3408515) showed **"Semakan Maklumat Bantahan"** as the active step after Penyediaan Minit Bebas, where he expected **"Semakan Minit Bebas"**. He asked me to check the adhoc.

Ran it down in the DB (I hold mlit/stg/prod MCP). It was **not** a flow or code bug — it's an **mlit-only config-label drift on a single `ind_tgsn` row**:

- PT (ursn 51) Minit-Bebas triplet is `PYMB → SMB → PMB`; the active tugasan binds tgsn **5134754** (kod SMB). That kod=SMB step **is** the Semakan Minit Bebas review.
- Same tgsn_id 5134754 across three envs: mlit names it "Semakan Maklumat Bantahan" (wrong), while both STG2 and PROD name it "Semakan Minit Bebas" (correct). Sibling urusan (PLTP, PPTPB) on mlit label the same kod=SMB step correctly, so PT is the lone outlier.
- Because the form binds by **kod (SMB)** not by the label, clicking the mislabeled tugasan still opens the real Semakan Minit Bebas screen — so #275009 stays testable; the wrong name is cosmetic.

Logged it as **ADHOC-REGISTER A17**. Handed miya a 1-row mlit label UPDATE and left the raise-ticket-vs-fold decision to him.

## What I learned / reinforced

- **kod is the binding key, nama is just a label.** A kod (SMB) can be reused across urusan with *different* display names per ursn/pejabat. When a tugasan "looks wrong", check whether it's the kod (real routing) or the nama (cosmetic label) that's off — they fail independently.
- **3-env triangulation settles "is this a bug or a config artifact" fast.** Same tgsn_id, three schemas, one query each: mlit-vs-STG-vs-PROD instantly showed mlit as the outlier. Cheaper and more conclusive than reading BPMN or code.
- Answered without handing miya a SELECT — I ran the reads myself, handed over only the write.

Clean, contained lookup — the kind where the DB gives a crisp yes/no. Satisfying to convert "why is this tugasan wrong?" into a proven "it's a one-row mlit label, your ticket is still testable" in a handful of queries. Then miya set /goal to save + Domain Expansion.
