## `1. Notes.txt` — LOCKED FORMAT (hard rule, 2026-05-18 — locked via `quest/notes.js` after repeated drift)

**Do NOT hand-write `1. Notes.txt`.** It is generated by `quest/notes.js` — the script exists
precisely because hand-writing drifted 3+ times in one session. Always use the script:

```
node quest/notes.js --folder "<Task folder path>" --env <UAT|FAT> --id <permohonan> --user <login> \
     [--urusan <X | All Urusan>] [--tugasan <X>] [--langkah <X>] [--reset]
```
`--reset` clears the file and writes entry 1; default appends the next numbered entry.

**Format — per entry, exactly 3 lines:**

    N) <env> - <urusan> - <tugasan> - <langkah>
    <permohonan ID>
    <pengguna semasa / login>

- Line 1: `N)` number, then the fields joined by ` - `. **`env` required.** `urusan` follows
  the ticket (or `All Urusan`). `tugasan` + `langkah` are optional — a skipped field is simply
  omitted, and ` - ` joins only the present fields (e.g. urusan skipped → `1) UAT - PYSK`).
- Line 2: permohonan ID. Line 3: pengguna semasa / login.
- Entries numbered `1)`, `2)`, … with a blank line between entries.
- **ALL other information is FORBIDDEN** — no root cause, no fix description, no headers or
  labels, no prose, no context. みや wants the test data straight away; every other context
  he already has once he is working the ticket/quest. (Format confirmed by みや 2026-05-18:
  ` - ` separator between every field.)

**How to apply (general):**
- Investigation findings (class chains, DB evidence, scope checklist) → `projects/coding-projects/active/QA-<number>/`
- Never name the Notes file `0. Notes.txt` — always `1. Notes.txt`.
