**Lessons that cost days (2026-09-10 → 21)**: (1) a text-match self-test passed a shipped bug (`api` undefined in run.js main scope, error swallowed → hand clock-in never detected) → test BEHAVIOUR with injected deps, never regex the source for a behaviour. (2) `schtasks /TR` turns `'` into `"` → an install path with an apostrophe silently points the task nowhere → XML registration. (3) "Interactive only" tasks at the LOGIN SCREEN are skipped, not queued (overnight Windows Update reboot) → CatchUp at-logon trigger. (4) My own test harness popped toasts on his desktop and he read it as "PymTime broke" → every harness sets `PYMTIME_NO_TOAST` + isolated `PYMTIME_HOME`; sims use `127.0.0.1:9` as Protime so no login leaves the laptop; the scheduler is only ever asked to RUN the harmless probe job (a Sim task would run `run.js --live` against the REAL home because Task Scheduler does not inherit env). (5) A bare `whoami` resolves to GNU whoami under Git Bash → full `System32` path. (6) A task registered with a past time today does NOT fire at registration (live-tested 150 s). (7) `dev/` is gitignored → new dev files need `git add -f` (the build gate was never actually committed until v14). (8) Windows PowerShell 5 reads a BOM-less .ps1 as ANSI → an em dash inside a string breaks parsing → .ps1 files stay pure ASCII. (9) He wants evidence (real eval output), not new version numbers.

**Portable build**: `build-portable.ps1` needs `$env:TEMP\node-portable.zip` (a zip containing node.exe); if missing, extract `node\node.exe` from the previous `PymTime-portable.zip` and re-zip it. Output ~32.6 MB, no install/admin.
